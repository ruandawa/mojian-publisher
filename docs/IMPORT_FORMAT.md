# 文章导入格式

墨笺导入后会先清理正文结构，将图片转换为本地 JPEG 资源，再通过统一排版生成阅读预览和发送内容。缺失或下载失败的图片会明确列出；文章准备未完成时不能进入发送队列。

## 支持文件

单文件支持 `.md`、`.markdown`、`.txt`、`.html` 和 `.htm`，文字使用 UTF-8，支持 UTF-8 BOM。TXT 按 Markdown 规则处理。

ZIP 图文包必须恰好包含一篇 `.md`、`.markdown`、`.html` 或 `.htm` 文章，另附图片。ZIP 中的 TXT 不作为文章候选。不能使用加密 ZIP，也不能包含绝对路径、`..` 路径穿越、重复文件路径或带冒号的路径。

带相对图片的文章请一起打包：

```text
article.zip
├─ article.md
└─ images/
   ├─ cover.jpg
   └─ photo.jpg
```

图片路径按文章所在目录解析，也可以引用 ZIP 内的兄弟目录，但不能越出整个包。单独上传 MD 或 HTML 不会同时读取其旁边的本地图片。

## Markdown 示例

```markdown
---
title: 给日常记录留一个清楚的入口
author: 示例作者
digest: 用标题、背景和下一步，把一条记录整理得更容易回看。
creation_source: unspecified
cover: images/cover.jpg
---

先写清楚主题，再补充必要的背景。

## 记下什么

用一个具体的小例子说明。

![图文说明](images/photo.jpg)

## 下一步做什么

- 写下一个可执行的小步骤。
- 暂时留存时，可以标注“备查”。

> 记录不必一次完整，能让下一次回看时理解即可。
```

Markdown 支持标题、段落、列表、引用、链接、粗体、斜体、代码、表格、行内图片和引用式图片。Markdown 内的原始 HTML 不作为 HTML 执行；需要导入 HTML 结构时使用 HTML 文件。

## Frontmatter 字段

文章开头可写 `---` 包围的单行 `key: value` 元数据。解析器支持简单单行字段及成对引号，不是完整 YAML 解析器；不要使用多行折叠、嵌套结构或 YAML 锚点。

- `title`：标题。未提供时，Markdown 优先读取一级标题，HTML 优先读取 `h1` 或 `title`；仍没有则使用文件名。最多保留 64 个字符。
- `author`：作者，最多保留 8 个字符。
- `digest`：摘要，最多保留 120 个字符。
- `cover`：封面图片地址，可使用包内相对路径或公开 HTTP(S) 地址。未指定时优先选正文第一张已准备好的图片；进入发送准备阶段仍没有时生成文字封面。
- `source_url`：原文页面的 HTTP(S) 地址，用于解析相对图片 URL，并作为下载时的 Referer。需要时可写 `https://example.com/articles/note.html`。
- `format`：写成 `html` 可明确按 HTML 解析；一般依据文件扩展名判断，无需填写。
- `creation_source`：`unspecified`、`ai` 或 `non_ai`。
- `ai_generated`：可选兼容字段，仅支持 `true` 或 `false`。

元数据字段区分大小写，推荐使用上述小写字段。标题、作者和摘要超长时会截取；导入后请在编辑器中检查。

## 创作来源

默认保持 `unspecified`，表示尚未确认；导入器不会根据文章主题、文件名或格式猜测来源。

- `ai`：文章含 AI 生成内容。
- `non_ai`：已确认文字和配图均非 AI 生成。
- `unspecified`：还未确认，发表需要声明时由用户补充。

`ai_generated: true` 等价于 `ai`，`false` 等价于 `non_ai`。若同时填写明确的 `creation_source`，两者必须一致，否则拒绝导入。示例默认使用 `unspecified`，请根据真实来源修改；随项目提供的 AI 辅助示例另有明确 `ai` 声明。

排期会冻结当时的创作来源。修改文章不会改变已排队任务的声明；应在排期前确认。

## 图片准备

支持公开 HTTP(S) 图片、ZIP 内图片和 base64 内嵌图片。HTML 也识别常见懒加载字段 `data-src`、`data-original`、`data-lazy-src`、`data-url`。公开图片下载需要地址无需登录即可读取，不能使用带用户名密码的 URL、本机或内网地址。

图片经解码和方向修正后保存为本地 JPEG。相同来源在一次准备中只下载一次，相同图片内容只保存一次；同一图片在正文中重复使用时保留每个位置。图片转成 JPEG 后不保留动画效果或原文件透明通道。

外链失效、防盗链、下载超时、内网地址、缺失文件、无法解码或不支持的图像会显示具体准备问题，不能靠忽略图片完成发送。生成的本地图片和原始文章保存在数据目录，原始 ZIP 也保留备份。

## HTML 与排版

HTML 支持正文常见结构，但会清理脚本、样式、iframe、表单、SVG、Math 等不可用或不安全节点。完整网页优先取唯一 `article`，否则取 `main` 或 `body`，并移除导航、页头、页脚和侧栏；多篇文章的网页请先整理为单篇正文。

导入后统一按软件主题排版，不保留原站任意 CSS。标题、段落、重点、列表、引用、代码、图注及图片保留层次与留白；宽表格转为适合手机阅读的纵向卡片。排版结果可在完整阅读预览中检查。

## 资源上限

- 单次导入文件或输入内容：60 MB。
- ZIP：最多 200 个归档条目，声明解压总大小最多 100 MB。
- 正文：最多 5 万字符；嵌入图片的数据不作为普通正文文字计算。
- 正文图片：最多 30 个出现位置，重复引用也计数；单独指定的封面不计入正文图片位置。
- 单张图片：最多 10 MB、2400 万像素。

这些是本工具的输入限制，不代表微信平台允许相同的全部内容、体积或账号操作。最终正文和图片还会在发送前核对，再由平台处理保存与发表。
